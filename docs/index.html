One session, moment by moment

Follow one session from start to finish and see which parts act at each moment.

40 parts work on their own

  1. In every session

    Rule files and settings are in effect from the first message on, with no hook involved.

    • Core rules Tells Claude to answer briefly, say what it has not verified and push back when a plan looks wrong.
    • Prompt flags Defines the flags, so -d, -nc or -p at the start or end of a message changes how Claude handles it.
    • Workflow rules Tells Claude to use plan mode when a task touches 3 or more files and to pick fitting skills itself.
    • Style and coding rules Tells Claude to write the minimum code that solves the request, in the project's existing style.
    • Sub-agents and model roles Sets the roles: Opus decides and checks every result, Sonnet workers do the work.
    • Status line Draws a line with account, model, effort, context and usage limits, and saves the limits to files.

  2. A session starts

    A session opens, resumes, is cleared or comes back from a compaction.

    • Compaction recovery Only after a compaction: tells Claude where the full transcript and your exact words are.
    • Session id Shows a line with the session id on start, on resume and after a clear.
    • Multiple Claude accounts On start and resume, links shared folders into the second account's folder and copies settings.json.

  3. You send a message

    You press Enter, and the hooks run before Claude reads the message.

    • Away mode Starts away mode on -away and ends it on -back; any other message keeps it on.
    • Session namer Sets the session title a background Haiku call came up with, and starts a new call when one is due.

  4. A skill fits the task

    A task matches a skill's description, so Claude loads that skill's full text.

    • Plain writing Loads when Claude writes prose other people will read: removes AI-writing tells, checks no fact was lost.
    • Diagram craft Loads when Claude draws a diagram by hand in SVG, HTML or Mermaid: type, layout, labels, accuracy.
    • UI craft Loads when Claude builds or reviews the look of an interface: rules against a generated look.
    • Video analysis Loads when you point at a video file or link: Claude looks at frames and reads the transcript.
    • Grilling Loads before Claude finalises a big plan that rests on things you have not confirmed: it interviews you.

  5. Claude is about to use a tool

    Before each tool call, the hooks get to look at it and can refuse it.

    • Away mode In away mode, denies a second question dialog and, past your stop point, everything but reads and notes.
    • Telegram notifications Only when the tool is AskUserQuestion: sends the question and its options to your Telegram chat.

  6. A permission prompt comes up

    Claude Code is about to show a permission prompt.

    • Bypass mode Answers "allow" when the request is for a Bash, PowerShell or Monitor command.

  7. Claude needs your attention

    Claude Code raises a notice, for example when Claude waits for your input.

    • Telegram notifications Sends the notice to your Telegram chat, unless it logged a finished turn here in the last 5 minutes.

  8. The conversation is compacted

    A long conversation is about to be shortened into a summary.

    • Compaction recovery Prints the summary instructions: keep your instructions, answers and decisions word for word, numbered.

  9. Claude finishes a turn

    Claude has finished answering and the turn ends.

    • Away mode If a usage limit was hit and no wake-up timer runs, tells Claude to start one that waits for the reset.
    • Handoff After 2 or more compactions, at 80% of the compact window, has Claude ask you about a handoff.
    • Telegram notifications Sends "Claude Responded" and the last answer to your Telegram chat, at most once per 20 seconds.

What you can start yourself

The other parts stay quiet until you start them yourself.

6 parts you start

  • Prompt flags

    Add a flag such as -d, -w, -q, -rc, -a, -p or -m at the start or end of your message.

    • "-d": discussion only, no edits or state-changing commands.
    • "-w": search the web first and cite what was found.
    • "-nc": no commits until you say so.
    All details

  • Away mode

    Add -away (or -away 85 for a weekly usage stop point) to your message; -back ends it.

    • "-away" on any message: one round of questions now, then it never asks or waits; later dialogs are blocked.
    • "-back" ends it. Any other message you send is answered or followed, and the work goes on.
    • "-away 85": also stops cleanly when your weekly usage reaches 85%.
    All details

  • Handoff

    Say "write a handoff" (add a session id to pass it on). A hook also suggests one when context gets big.

    • "write a handoff": the job, every decision, your own words, status and next steps go to ~/.claude/handoffs.
    • "pass this to session <id>": Claude checks it can reach that session, sends the handoff and checks it arrived.
    • No target session: you get one start line to paste into a new session in the same folder.
    All details

  • Architecture decisions

    Type /architecture with the decision or system.

    • "/architecture Should we use Kafka or SQS?": a decision record with options, trade-offs and consequences.
    • "/architecture Review this microservices proposal": an evaluation of a design you hand it.
    • "/architecture Design the notification system": a new component designed from requirements.
    All details

  • Usage tools

    Run the report scripts in ~/.claude/tools when you want a cost or usage report.

    • "node ~/.claude/tools/usage-audit.mjs": API-equivalent cost per account for the last 7 days.
    • Add --start and --end for another time window, and --out to save the report.
    • "node ~/.claude/tools/audit-transcripts.mjs --since 2026-11-01 --until 2026-11-07": a full transcript audit.
    All details

  • Multiple Claude accounts

    Type claude -P (or your chosen flag) to start the second account.

    • "claude" opens one account and "claude -P" the other, both signed in at the same time.
    • Any two accounts, for example work and personal. You choose their labels and the flag.
    • Settings, skills, hooks, plugins and sessions are shared; login, plan and usage limits stay separate.
    All details

Steer one message with a flag

Put flags at the start or end of a message. They combine and the stricter wins.

  • -ddiscussion only, no edits or state-changing commands.
  • -wsearch the web first and cite what was found.
  • -ncno commits until you say so.
  • -qClaude asks before acting if anything is unclear.
  • -rcextra rigor: verify end to end, re-run checks, say what could not be verified.
  • -aanalyze deeply first: read files, trace logic, weigh options.
  • -pplan mode and a plan for approval, even for a small task.
  • -mkeep it for good: a rule goes to CLAUDE.md, a fact to memory.
  • -awayleave and let Claude finish alone; "-back" ends it. Both come with the Away mode part.

    How it stays yours

    Every change arrives as a proposal with its real diff, and a rollback restores only what sync wrote.

    Join

    1. You

      Clone the repo, open Claude Code in it and say “Follow START.md”.

    2. The setup

      Checks the PC for Windows, Git Bash, Node and Claude Code, and stops if one is missing.

    3. The setup

      Installs only the sync tool and its skill, and remembers where the clone is.

    4. The setup

      Asks about each part on its own: what it is, what it solves, its use cases, what it changes on the PC and what it costs.

    5. You

      Answer install or skip for each part, then give one last yes.

    6. The setup

      Installs what you chose and gives a short report. A file it replaces keeps a backup.

    Nothing is installed until you say so.

    Stay up to date

    1. You

      Say “sync my setup”.

    2. The setup

      Fetches the repo and lists the pending proposals.

    3. The setup

      Shows each proposal on its own: what and why, token cost, how well it was tested, what it runs and the real diff.

    4. You

      Answer accept, skip or later. Later comes back next time, skip does not.

    5. The setup

      Where your own file or setting differs, asks whether to keep yours or take the new one.

    6. The setup

      Applies what you accepted and ends with a one-screen report.

    Nothing updates in the background.

    Go back

    1. You

      Say “roll back my last sync” or “go back to version <tag>”.

    2. The setup

      Shows the plan in plain words: files that change back, settings that revert, MCP servers removed, proposals that will be offered again.

    3. You

      Answer yes or no. It applies only after a yes.

    4. You

      For each file you edited, choose: keep my file, or revert it. A backup is kept.

    5. The setup

      Restores only what sync wrote. Your own files, settings and edits stay.

    Rolled-back changes are offered again on the next sync.
